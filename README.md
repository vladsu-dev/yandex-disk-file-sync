# Синхронизация файлов с Яндекс Диском

CLI-сервис на Python, который поддерживает облачное зеркало локальной папки. Он загружает новые файлы, заменяет изменившиеся и переносит лишние облачные копии в Корзину Яндекс Диска. Доступны разовый проход и постоянная синхронизация по интервалу.

**Источник истины — локальная папка.** Первый проход тоже перемещает в Корзину файлы, которых нет в источнике. Для знакомства с программой используйте отдельную пустую папку на Диске.

## Быстрый старт

Понадобится Python 3.11 или новее. Выполните в корне репозитория на macOS или Linux.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdir -p sync-source
cp .env.example .env
```

На Windows используйте `py -3.11 -m venv .venv`, `.venv\Scripts\Activate.ps1`, `New-Item -ItemType Directory sync-source` и `Copy-Item .env.example .env` в PowerShell.

1. Создайте на Яндекс Диске пустую папку `FileSyncDemo` или укажите другой существующий путь в `REMOTE_DIR`.
2. Получите OAuth-токен приложения с правами `cloud_api:disk.read` и `cloud_api:disk.write` и сохраните его в `YANDEX_DISK_TOKEN` внутри `.env`. [Инструкция Яндекса](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart)
3. Положите пробный файл в `sync-source` и выполните `python -m file_sync --once`. Проверьте облачную папку и журнал.
4. Выполните `python -m file_sync` для периодического запуска. Остановка — Ctrl+C.

| Ключ | Назначение |
| --- | --- |
| `LOCAL_DIR` | Существующая папка с исходными файлами |
| `REMOTE_DIR` | Существующая папка Диска, например `disk:/FileSyncDemo` |
| `YANDEX_DISK_TOKEN` | OAuth-токен приложения |
| `SYNC_INTERVAL` | Пауза между проходами в секундах |
| `LOG_FILE` | Путь к журналу вне папки источника |

Относительные пути вычисляются от каталога с `.env`. Настройки и журнал должны находиться вне источника. Для одной пары папок запускайте один экземпляр программы.

## Как работает синхронизация

| Состояние | Действие |
| --- | --- |
| Файл есть только локально | Загрузка |
| Файл есть в обеих папках, хеши различаются | Замена облачной копии |
| Хеши совпадают | Пропуск |
| Файл есть только в облаке | Перемещение в Корзину |

Сервис обрабатывает обычные файлы верхнего уровня. Вложенные папки и символические ссылки пропускаются. Содержимое сравнивается по SHA-256 или по MD5, если API не вернул SHA-256. При неполном списке файлов запись откладывается. Если проверка или загрузка файла завершилась ошибкой, в этом проходе облачные удаления пропускаются.

Правила сверки находятся в [file_sync/sync.py](file_sync/sync.py), клиент REST API — в [file_sync/yandex_disk.py](file_sync/yandex_disk.py), настройки — в [file_sync/config.py](file_sync/config.py). Проект использует `requests`, `python-dotenv` и `Loguru`.

## Проверки

```bash
python -m unittest discover -s tests -v
python -m file_sync --help
```

Тесты работают с временными файлами и подменой HTTP, токен им не требуется. Для проверки с настоящим Диском создайте, измените и удалите пробный файл, запуская `--once` после каждого действия. Коды возврата: `0` — успех, `1` — ошибка прохода, `2` — ошибка аргументов, настроек или доступа к папке.
