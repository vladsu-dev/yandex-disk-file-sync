# Синхронизация файлов с Яндекс Диском

Сервис зеркалирует обычные файлы из одной локальной папки в одну существующую папку Яндекс Диска. Первый проход выполняется сразу. Затем программа ждёт заданный интервал и повторяет сверку до остановки через Ctrl+C.

**Локальная папка определяет содержимое зеркала.** Файлы, которые есть только в облачной папке, перемещаются в Корзину Яндекс Диска уже при первом проходе. Для первой проверки создайте отдельную пустую папку на Диске.

## Запуск

Нужен Python 3.11 или новее. Выполните в корне проекта на macOS или Linux.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdir -p sync-source
cp .env.example .env
```

В Windows PowerShell используйте `py -3.11 -m venv .venv` или укажите установленную более новую версию. Активируйте окружение командой `.venv\Scripts\Activate.ps1`, создайте папку командой `New-Item -ItemType Directory sync-source` и скопируйте настройки через `Copy-Item .env.example .env`.

1. Создайте на Яндекс Диске папку `SkillboxFileSync`.
2. Получите OAuth-токен приложения с правами `cloud_api:disk.read` и `cloud_api:disk.write`. Вставьте только значение токена в `YANDEX_DISK_TOKEN`. [Инструкция Яндекса](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart)
3. Положите пробный файл в `sync-source` и запустите `python -m file_sync --once`. Откройте папку на Диске и журнал `logs/file-sync.log`.
4. Для постоянного опроса запустите `python -m file_sync`. Процесс работает, пока открыт терминал или пока его поддерживает менеджер процессов.

В PyCharm откройте папку проекта, выберите интерпретатор из `.venv` и задайте рабочим каталогом корень проекта. Запускайте модуль `file_sync` или используйте те же команды в терминале IDE.

Если нужно оставить процесс работать после закрытия терминала на macOS или Linux, сначала проверьте запуск с `--once`. Затем запустите его из корня проекта.

```bash
mkdir -p logs
nohup .venv/bin/python -m file_sync > logs/console.log 2>&1 &
echo $!
```

Последняя команда выводит PID. Остановить этот экземпляр можно командой `kill PID` с полученным числом. Используйте один экземпляр на пару папок.

### Настройки

| Ключ | Назначение |
| --- | --- |
| `LOCAL_DIR` | Существующая локальная папка с исходными файлами |
| `REMOTE_DIR` | Существующая папка Диска, например `disk:/SkillboxFileSync` |
| `YANDEX_DISK_TOKEN` | OAuth-токен приложения Яндекса |
| `SYNC_INTERVAL` | Положительная пауза в секундах после прохода |
| `LOG_FILE` | Файл журнала вне локальной папки синхронизации |

Относительные пути разрешаются от каталога с `.env`. Файл настроек и журнал должны находиться вне источника. `.env` исключён из Git. Шаблон `.env.example` содержит пустое поле для токена.

В ТЗ одновременно перечислены Requests, python-dotenv и Loguru и указано ограничение на сторонние пакеты. Здесь использованы три прямо требуемые библиотеки. Тесты написаны на стандартном `unittest`.

## Правила синхронизации

| Состояние | Действие |
| --- | --- |
| Файл есть только локально | Загрузить с `overwrite=false` |
| Файл есть в обеих папках, но хеш отличается | Перезаписать облачную копию |
| Хеши совпали | Оставить файл как есть |
| Файл есть только в облачной папке | Переместить в Корзину Диска |
| Список одной из папок не получен целиком | Отложить операции до следующего прохода |

Проверяется только первый уровень папки. Вложенные папки, символические ссылки и специальные локальные файлы пропускаются. Одноимённая пропущенная локальная запись удерживает облачный файл от удаления. Облачные папки сохраняются.

Хеш SHA-256 сравнивает содержимое без привязки к разнице между локальным и облачным временем. При отсутствии SHA-256 используется доступный MD5. Если в облаке нет обеих сумм, проход откладывается. Изменения, сделанные непосредственно в облаке, могут быть перезаписаны или отправлены в Корзину на следующем проходе.

При недоступности сети или отдельного файла ошибка пишется в журнал. Если файл не удалось проверить или загрузить, удаления откладываются на следующий проход. Например, при переименовании файла старая облачная копия сохранится до успешной загрузки файла с новым именем. Следующий проход снова сравнивает папки с текущим состоянием. HTTP 401 от API и HTTP 403 при проверке доступа к папке или удалении выводят подсказку проверить токен и права. HTTP 403 или 507 при запросе ссылки загрузки может означать нехватку места. В этом случае программа сообщает, что проверить, и продолжает работу. При HTTP 404 для папки проверьте `REMOTE_DIR`. При постоянном запуске такие ошибки конфигурации требуют перезапуска после исправления.

## Где читать код

| Файл | Ответственность |
| --- | --- |
| `file_sync/__main__.py` | Аргументы запуска, настройка журнала, пауза и коды выхода |
| `file_sync/config.py` | Чтение `.env` и проверка путей |
| `file_sync/sync.py` | Один проход и решение, когда вызвать загрузку, замену или удаление |
| `file_sync/local_files.py` | Список имён, открытие обычного файла и вычисление хеша |
| `file_sync/storage.py` | Метаданные и ошибки, общие для клиентов хранилищ |
| `file_sync/yandex_disk.py` | Публичные методы `load`, `reload`, `delete`, `get_info` и HTTP-запросы |
| `tests/` | Проверки конфигурации, сверки папок и запросов |

Клиент облака получает токен и путь в конструкторе. `sync.py` работает с переданным объектом через четыре метода, поэтому для другого хранилища можно написать свой клиент с тем же интерфейсом.

## Проверка

```bash
python -m unittest discover -s tests -v
python -m file_sync --help
```

Тесты проверяют реальные операции с временными файлами и подменяют транспорт HTTP. Они не требуют токена. Для ручной приёмки последовательно создайте, измените и удалите пробный файл. Запустите `--once` после каждого действия и сверяйте папку на Диске, Корзину и журнал.

Коды `--once`:

- `0` — проход выполнен
- `1` — зафиксирована ошибка синхронизации, включая временный сетевой сбой
- `2` — исправьте аргументы запуска, настройки или доступ к облачной папке

[Документация REST API Яндекс Диска](https://yandex.ru/dev/disk-api/doc/ru/)
